```
git remote -v 
```
Список подключенных репозиториев с их URL для операций fetch и push.

```
git remote add <name> <URL>
```
Связывает локальный репозиторий с удалённым.

```
git remote set-url <name> <newurl>
```
Позволяет сменить адрес удалённого репозитория(например, при переходе с SSH на HTTPS).

```
git remote rename <old> <new>
```
Меняет имя алиаса.

```
git remote remove <name>
```
Удаляет запись о соединении из локальной конфигурации.

## Fetch, pull, push

```
git fetch
```
Безопасная команда, скачивающая коммиты, файлы и ссылки из удалённого репозитория в локальный, не изменяя текущую рабочую директорию и не сливая изменения автоматически.

```
git pull
```
Скачивает изменения из удалённого репозитория и автоматически объединяет их с текущей веткой. По сути, это комбинация двух операций: git fetch и git merge(или git rebase).

```
git pull --rebase
```
Вместо слияния используется rebase.

```
git pull origin main
```
Загружает ветку main из удалённого репозитория origin и объединяет её с текущей веткой.

```
git push origin main
```
Отправляет локальную ветку main в удалённый репозиторий.

```
git push -u origin main
```
Связывает локальную ветку с удалённой(upstream). Позволяет использовать git push без указания имени репозитория и ветки.

```
git push --all
```
Загружает все локальные ветки одновременно.

```
git push --force(или --force-with-lease - более безопастно)
```
Принудительная отправка: перезаписывает историю удалённой ветки.

---

## Порядок действий перед push:

1. Убедиться, что изменения добавлены в индекс(git add).
2. Убедиться, что изменения зафиксированы(git commit).
3. Выполнить git fetch или git pull, если удалённый репозиторий содержит изменения, которых нет локально.
4. Выполнить git push
