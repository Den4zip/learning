```
git merge <branch_name>
```
Позволяет слить текущую ветку и указанную в одну. Если изменения в одних и тех же строках выдаст ошибку. Пользователю нужно будет в редакторе поменять конфликтные строки. История слитой ветки сохраняется. Основа стратегии GitFlow.

```
git merge --abort
```
Отменить слияние.

---

## Маркеры конфликтов:

- `<<<<<<< HEAD` (или `<<<<<<< name`) обозначает начало блока с вашей версией кода.
- `=======` служит разделителем между двумя конфликтующими версиями.
- `>>>>>>> feature-branch` (или `>>>>>>> name`) указывает конец блока с версией из другой ветки.

## Rebase

```
git rebase <branch_name>
```
Позволяет слить текущую ветку в указанную, поместив её наверх указанной. История не сохраняется, ветка выглядит прямой, без ветвления. Основа стратегии Trunk-Based Development.

```
git rebase --continue
```
Продолжить rebase после разрешения конфликтов.

```
git rebase --abort
```
Отменить rebase.

---
## Rebase -i

```
git rebase -i <branch_name>
```
Позволяет открыть в интерактивном режиме(текстовый редактор) со списком коммитов в хронологическом режиме.
Основные команды:
- pick - p - оставить коммит без изменений
- reword - r - оставить изменения коммита, но изменить только сообщение
- edit - e - остановить коммит и приостановить rebase на нём, чтобы внести изменения в код или разбить коммит
- squash - s - объединить коммит с предыдущим и склеить их сообщения
- fixup - f - объединить коммит с предыдущим, но выкинуть сообщение этого коммита, оставив предыдущее
- drop - d - полностью удалить коммит из истории
